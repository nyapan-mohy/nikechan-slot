# 現行残タスク実装プラン

## 目的

現行仕様で公開用エミュレーターへ進めるため、未完了の作業だけを優先度順に残す。

完了済みの仕様穴埋め、確率調整、簡易スランププレビューは `docs/plan/archive/completed-spec-and-simulation-tasks-2026-05-03.md` に移した。

## P0: プロトタイプを実装用構造へ移す

0. 3リールの役配置を設計する。
   - 詳細タスクは `docs/plan/reel-layout-design-task.md` を正とする。
   - 現在の図柄素材を前提に、左、中、右リールの配列案を作る。
   - 通常小役、レア小役、BIG、REG、ハズレ目、リーチ目の停止制御に耐える配置にする。

1. `index.html` に入っているデータとロジックを分離する。
   - `src/data/` に図柄、リール配列、ライン、役、払出、抽選テーブル、ボーナス仕様を置く。
   - `src/core/` に抽選、状態遷移、停止制御、入賞判定、払出、イベント出力を置く。
   - UI、ログ表示、デバッグ操作は `src/ui/` または `src/emulator/` 側へ分ける。

2. ボーナス状態の実ゲーム処理を完成させる。
   - 通常時は3枚掛け。
   - ボーナス中は2枚掛け。
   - ボーナス中は成立ベルOnly。
   - 1Gあたり14枚払出、純増12枚。
   - BIGは21G、純増252枚で終了。
   - REGは8G、純増96枚で終了。
   - 終了演出後に通常へ戻す。

3. イベント出力を正式化する。
   - `gameStarted`
   - `betAccepted`
   - `lotteryResolved`
   - `reelStopped`
   - `winEvaluated`
   - `payoutApplied`
   - `bonusFlagRaised`
   - `bonusSymbolEntered`
   - `bonusStarted`
   - `bonusEnded`
   - `stateChanged`
   - `creditChanged`
   - `settingChanged`
   - `simulationStopped`

## P1: 停止制御と入賞判定を詰める

1. ボーナス優先の停止制御を実装する。
   - 同時成立時はボーナス図柄を最優先で引き込む。
   - 引き込めない場合のみ、成立小役またはリプレイを入賞させる。
   - ボーナス待機状態では新規ボーナス抽選を行わない。
   - ボーナス待機状態で引き込めない場合はリーチ目を出す。

2. 小役の停止制御を実装する。
   - `BELL` は目押しなしで揃う。
   - `RARE_CHERRY` は目押し範囲内のみ揃う。
   - `SUIKA` は目押し範囲内のみ揃う。
   - 未成立役を有効ラインに揃えない。
   - 角チェリーの2ライン判定を固定する。

3. リーチ目と取りこぼし停止形を増やす。
   - ボーナス待機状態のリーチ目パターンを定義する。
   - レア小役取りこぼし時の停止形を定義する。
   - ハズレ時に誤入賞しない停止形を定義する。

## P2: 検証機能を作る

1. 単体テストを作る。
   - 同じシードで同じ結果になる。
   - 抽選テーブルの重み合計が `65536` になる。
   - 設定別にBIG/REG/BELL/REPLAYが変化する。
   - CHERRY/SUIKA/ボーナス重複チェリーは全設定共通になる。
   - 払出とクレジット差分が仕様通りになる。
   - ボーナス成立、待機、入賞、消化、終了が分離される。
   - 未成立役が揃わない。

2. バッチシミュレーターを作る。
   - 設定別に任意ゲーム数を実行できる。
   - 機械割、50枚ベース、BIG/REG確率、小役確率を出力する。
   - 期待値とのズレを検出する。
   - シード指定で再現できる。

## P3: 表示と操作を実装する

1. 第一段階ログUIを正式化する。
   - 1ゲーム実行。
   - ボーナスまで実行。
   - 強制BIG/REG。
   - オートモード。
   - リールWaitなし。
   - メイン基板相当ログの固定フォーマット。

2. データ表示端末を作る。
   - 現在状態。
   - 動作回転数。
   - ボーナス間ゲーム数。
   - BIG回数。
   - REG回数。
   - 大当たり確率。
   - 小役成立数と小役成立確率。
   - スランプグラフ。

3. HTML + Canvas の統合UIへ進める。
   - 内部状態。
   - 筐体表示。
   - 筐体動作。
   - シミュレーション用操作。
   - データ表示端末。
   - スランプグラフ。
   - メイン基板ログ。

## P4: 公開準備

1. 仮素材を整える。
   - 既存メーカー、既存機種、既存図柄、既存音源、既存告知ランプ意匠を避ける。
   - 公開可能な画像と音源だけを使う。

2. 公開用注意書きを整える。
   - エミュレーターであることを明記する。
   - 実機検定を通したものではないことを明記する。
   - 実機化、基板回路、法規対応は別作業であることを明記する。

3. ブラウザ確認を行う。
   - ローカル表示。
   - 操作性。
   - 表示崩れ。
   - Canvas描画。
   - ログとデータ表示端末の整合。

## 後回しにするもの

- 基板回路。
- 実機筐体製造。
- 型式試験申請向けの正式資料。
- 音、ランプ、液晶演出の本制作。
- 設定看破用のボーナス中小役差分。
